## 1. Application-Level Database Driver Architecture

Horizon Portal uses Prisma ORM with dual-engine capabilities:
- **Local Development / Offline Testing:** SQLite engine accessing `prisma/dev.db`.
- **Cloud Preview & Production:** PostgreSQL engine configured via `prisma/schema.postgresql.prisma`.

### Client Instantiation Pattern (`src/lib/prisma.ts`)
```typescript
import { PrismaClient } from '@prisma/client';

declare global {
  var prisma: PrismaClient | undefined;
}

export const prisma =
  globalThis.prisma ||
  new PrismaClient({
    log: process.env.NODE_ENV === 'development' ? ['query', 'error', 'warn'] : ['error'],
  });

if (process.env.NODE_ENV !== 'production') {
  globalThis.prisma = prisma;
}
```

## 2. Dynamic Connection Resolution

1. **Environment Binding:**
   The Next.js runtime binds `process.env.DATABASE_URL` upon container startup.
   - When running on Vercel Preview, Next.js injects the Preview-scoped environment variable.
   - If `DATABASE_URL` points to an isolated Neon branch endpoint, all queries generated by `src/lib/prisma.ts` are automatically routed to the preview database.
2. **Schema Uniformity:**
   Both Production and Preview share the identical relational schema defined in `prisma/schema.postgresql.prisma`.
3. **Fail-Closed Safety Guard:**
   If `DATABASE_URL` is empty, Prisma Client immediately fails to initialize, returning HTTP 500 error responses and preventing any unauthenticated or unauthorized data leakage.
