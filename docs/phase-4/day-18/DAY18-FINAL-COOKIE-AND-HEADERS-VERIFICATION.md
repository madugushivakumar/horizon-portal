## 1. Authentication Cookie Architecture (`src/lib/auth/session.ts`)

### Configuration & Properties
Authentication session cookies are generated by `setSessionCookie()` using `getSessionCookieOptions()`:

| Cookie Attribute | Configured Value | Security Purpose | Verification Status |
|---|---|---|:---:|
| **Cookie Name** | `horizon_session` | Standard application session identifier | Verified |
| **HttpOnly** | `true` | Prevents access via client-side JavaScript (`document.cookie`), mitigating XSS token theft | Verified |
| **Secure** | `process.env.NODE_ENV === "production"` | Enforces transmission strictly over HTTPS encrypted connections in production | Verified |
| **SameSite** | `lax` | Prevents Cross-Site Request Forgery (CSRF) on state-changing requests while permitting top-level navigation | Verified |
| **Path** | `/` | Scoped to the entire portal application domain | Verified |
| **Max-Age** | `28,800` seconds (8 hours) | Bounded session lifetime matching corporate working day shift | Verified |

### Lifecycle & Invalidation Verification
1. **Login (`POST /api/v1/auth/login`):** Appends `Set-Cookie: horizon_session=<jwt>; Path=/; Max-Age=28800; HttpOnly; SameSite=Lax`.
2. **Logout (`POST /api/v1/auth/logout`):** Overwrites cookie with `maxAge: 0`, `expires: new Date(0)`, and empty value to ensure client browser clears the cookie immediately.
3. **Session Invalidation (`GET /api/v1/auth/me`):** If an account is deactivated or the token is invalid, `clearSessionCookie(response)` is called automatically.
4. **Production Demo Session Guard (`GET /api/v1/auth/demo-session`):** In production, returns HTTP 404 immediately; zero cookies are issued.

## 2. HTTP Security Headers Verification

Security headers are implemented in `src/lib/security/headers.ts` and enforced via two complementary layers:
1. **Next.js Global Config (`next.config.ts`):** Injected via `headers()` for all routes (`/:path*`).
2. **Edge Proxy Middleware (`src/proxy.ts`):** Applied to every `NextResponse` (including redirects, 401 unauth, and 403 forbidden responses) via `applySecurityHeaders()`.

| Header Name | Configured Directive / Value | Standard / Specification |
|---|---|---|
| **X-Content-Type-Options** | `nosniff` | RFC 7231; prevents MIME-type sniffing |
| **X-Frame-Options** | `DENY` | RFC 7034; prevents UI clickjacking (harmonized with CSP `frame-ancestors 'none'`) |
| **Referrer-Policy** | `strict-origin-when-cross-origin` | W3C Referrer Policy; strips path/query on cross-origin requests |
| **Permissions-Policy** | `camera=(), microphone=(), geolocation=(), browsing-topics=(), payment=()` | W3C Permissions Policy; disables unused sensitive APIs |
| **Strict-Transport-Security (HSTS)** | `max-age=31536000; includeSubDomains` (Production only) | RFC 6797; enforces 1-year HTTPS and subdomain coverage. Omitted in development to prevent localhost lockout. |

## 3. Content Security Policy (CSP) Option C Architecture & Analysis

### Approved Directive String
```text
default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com data:; img-src 'self' data: blob:; connect-src 'self'; frame-src 'none'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests
```

### Forensic Hash Analysis & W3C CSP Level 3 Rule
- **Inline Theme Script:** Located in `src/components/ThemeProvider.tsx` (218 bytes).
- **Calculated SHA-256 Digest:** `sha256-u/P+mH0lAjjBdDDWdyZ4AkPHaWjLh8LuvYG0f8MkXiE=`.
- **Architectural Decision (Option C):** This hash is **INTENTIONALLY NOT INJECTED** into the production CSP `script-src` directive.
  - *W3C CSP Level 3 Specification:* If a CSP directive specifies *any* hash or nonce source, browsers that support CSP Level 3 will automatically ignore `'unsafe-inline'`.
  - In Next.js 16 with React 19, React Server Components stream inline flight chunks (`<script>(self.__next_f=self.__next_f||[]).push(...)</script>`). Injecting the theme script hash would cause modern browsers to suppress `'unsafe-inline'`, breaking Next.js hydration and crashing the portal UI.
  - Therefore, Option C (`'self' 'unsafe-inline'`) without hash sources is the proven, stable production architecture.

### Residual Risk Disclosure
Because `'unsafe-inline'` is permitted in `script-src`, CSP does not protect against stored XSS if an attacker can inject raw HTML into the DOM. This residual risk is mitigated through comprehensive input validation (Zod in Stage D), React's default auto-escaping of JSX text nodes, and strict JSON API response serialization.
